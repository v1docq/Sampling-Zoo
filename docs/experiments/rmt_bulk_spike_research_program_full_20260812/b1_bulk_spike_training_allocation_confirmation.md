# B1: распределение обучающего бюджета и выигрыш относительно B0

Источник: `04_bulk_spike_confirmation/routing_geometry_runs.jsonl` из запуска
`run_rmt_bulk_spike_research_program_20260812` на сервере. В таблицу включены
только 12 конфигураций, в которых политика `B3_validation_selected` выбрала
`B1_bulk_single_spike` вместо fallback `B0_standard_A9`.

## Как читать таблицу

`budget` — доля от `n_train`, доступная B1 для обучения. Эта подвыборка
разбивается без пересечений на две части: `bulk` и `spike`; суммарный размер
в точности равен бюджету. Это не «общая bulk-модель плюс эксперт»: B1 обучает
два эксперта, каждый на своей части бюджетной подвыборки. `gain_vs_b0` —
изменение основной тестовой метрики относительно B0; положительное значение
означает улучшение. Для регрессии основной метрикой является RMSE, для
классификации — LogLoss.

## Наблюдения

- Самые устойчивые положительные результаты B1 видны при почти равном
  разделении бюджета: `elevators` при 1% и `segment` при 5--10%.
- Один отрицательный случай `elevators` также имеет практически симметричное
  разделение 50/50. Само соотношение bulk/spike не объясняет успех без учёта
  конкретной подвыборки, seed и спектральной структуры.
- `house_16H` показывает, что даже малый spike-сегмент (2.7% бюджета) может
  быть полезен. Это аргумент против фиксированного минимального процента
  spike-части.
- Для `vehicle` вывод следует считать предварительным: при бюджете 1% каждый
  эксперт обучается всего на трёх строках.

Для следующего повтора стоит дополнительно сохранять распределение строк
отложенной выборки по двум экспертам: hard assignment и soft routing mass.
Это позволит отделить эффект размера обучающего spike-сегмента от эффекта
фактического использования spike-эксперта при предсказании.
