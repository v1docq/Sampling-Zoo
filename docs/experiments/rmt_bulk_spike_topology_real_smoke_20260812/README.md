# Smoke-проверка реального контура bulk/spike

## Назначение

Проверка подтверждает, что единый контур эксперимента работает для регрессии и многоклассовой классификации до запуска OpenML-пилота. В запуск вошли две синтетические задачи, один `seed`, бюджет `20%`, модель `ridge` и четыре варианта топологии `B0-B3`.

## Результат

- Сохранено `8/8` завершённых записей без ошибок.
- Варианты `B1` и `B2` сохранили точный бюджет и не использовали строку более одного раза.
- Для классификации рассчитаны `log_loss`, Brier score, ECE, `F1 macro` и минимальная полнота класса.
- Для обеих задач один раз обучена модель на полном обучающем наборе; относительно неё рассчитана деградация каждого бюджетного варианта.
- `B3` выбрал безопасный возврат к `B0` на обеих задачах: строгий критерий не принял специализацию по одной точке наблюдения.
- Исследовательский критерий допуска имеет статус `failed` только из-за отсутствия выбранной специализации. Это ожидаемо для smoke-проверки с одним `seed` и не означает сбой программного контура.

## Артефакты

- `routing_geometry_runs.jsonl`: инкрементальный журнал запусков.
- `routing_geometry_replay.csv`: плоская таблица метрик и диагностик.
- `bulk_spike_paired.csv`: попарное сравнение с `B0`.
- `bulk_spike_summary.csv`: агрегированная сводка.
- `bulk_spike_gate.json`: результат строгого критерия допуска.
- `bulk_spike_full_references.jsonl`: инкрементальный журнал полноразмерных опорных моделей.
- `bulk_spike_full_references.json`: снимок опорных метрик, времени и сложности моделей.
- `bulk_spike_report.md`: автоматически сформированный отчёт.
- `bulk_spike_gain_by_budget.png`: проверенная визуализация выигрыша относительно `B0`.

Следующая проверка должна использовать четыре реальных пилотных датасета, пять `seed` и бюджетную сетку `(0.01, 0.05, 0.10, 0.20)`.
