# Контракты топологии bulk/spike

## Реализованные границы

`BulkSpikeExpertTopologySpec` задаёт число экспертов, минимальный размер партиции, способ распределения бюджета, порог сигнальности и геометрию маршрутизации в spike-ветви. `BulkSpikePartitionContract` проверяет три обязательных инварианта: точный общий бюджет строк, отсутствие повторов и ограничение числа экспертов.

`BulkSpikeBudgetAllocator` поддерживает одну общую spike-модель и несколько моделей по устойчивым спектральным компонентам. Если бюджет или число надёжных компонент недостаточны, multi-spike вариант детерминированно сводится к single-spike. Малые spike-группы не создаются.

`BulkSpikeHierarchicalRouter` сначала вычисляет мягкую вероятность принадлежности к spike-режиму, затем распределяет её между spike-экспертами. Условные веса могут быть получены из shrinkage Mahalanobis или GMM posterior. Итоговые вероятности неотрицательны и суммируются в единицу по каждой строке.

`CrossFittedBulkSpikeTopologySelector` выбирает B1 или B2 только по внутренним фолдам. При нестабильном результате сохраняется B0. B4 остаётся диагностическим оракулом и не может быть материализован как рабочая топология.

## Проверенные инварианты

- точный бюджет и глобальная уникальность строк;
- одинаковое ограничение на число экспертов;
- отсутствие пустых партиций;
- минимальный размер multi-spike партиции;
- эквивариантность маршрутизации к перестановке имён spike-экспертов;
- корректная нормировка вероятностей;
- откат multi-spike к single-spike при недостатке данных;
- выбор B2 при устойчивом выигрыше на внутренних фолдах.
