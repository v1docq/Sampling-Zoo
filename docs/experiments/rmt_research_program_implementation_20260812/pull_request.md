# Семиэтапная проверка классификации и bulk/spike-топологии RMT

## 1. Почему появился этот PR

Предыдущие RMT-эксперименты подтвердили пользу защищённого выбора геометрии для
регрессии, но оставили четыре существенных пробела. Для классификации не было
отдельного критерия безопасности по вероятностным метрикам и полноте классов.
Политика `capped_leverage` применялась глобально, хотя её преимущество зависит
от задачи и бюджета. Гипотеза о разделении спектра на bulk и spikes имела
диагностику, но не имела топологии обучения с точным общим бюджетом. Наконец,
оценка деградации качества не была привязана к полнообъёмному эталону и плотной
сетке бюджетов.

Из-за этого нельзя было обоснованно переходить к полной AMLB-сетке: улучшение
на отдельных задачах могло скрывать утечку тестовых данных, потерю редких
классов, превышение бюджета или неустойчивый выбор специализации.

## 2. Что он меняет или стремится улучшить в текущей базе

PR добавляет единый семиэтапный исследовательский контур для регрессии и
классификации. Каждый этап имеет типизированный контракт, зависимости,
ожидаемое число записей и жёсткий критерий перехода. Результаты сохраняются
инкрементально, а совместимый запуск можно возобновить без повторного расчёта
завершённых этапов.

Локально подтверждены архитектурные и вычислительные инварианты. Строгий
синтетический критерий завершён на 1260 из 1260 запусков; 94,12% выбранных
специализаций улучшили B0, медианный выигрыш составил 19,27%, а худшее
подтверждающее ухудшение не превысило 0,0904%. Проверка на четырёх реальных
задачах сформировала 16 из 16 записей без ошибок и подтвердила сохранение
классов, вероятностные контракты и точный бюджет. На одном значении генератора
научная эффективность bulk/spike не заявляется: её должен проверить
многоразовый серверный пилот.

## 3. За счёт каких решений и методов он это делает

- Защищённый классификационный селектор A10 использует ROC AUC для бинарных и
  log loss для многоклассовых задач. Дополнительные ограничения контролируют
  Brier score, ECE, `F1 macro`, худшую полноту класса и сохранение классов в
  партициях.
- Селектор этапа S.1 сравнивает `uniform` и `capped_leverage` на независимых
  внутренних фолдах. При недостаточных доказательствах он возвращается к
  равномерной выборке.
- Топологии B1 и B2 обучают широкий bulk-эксперт и один или несколько
  spike-экспертов. Планировщик сохраняет одинаковый уникальный бюджет строк с
  B0, а B3 выбирает топологию только по внутренней валидации.
- Синтетический критерий разделяет нулевой спектр, одиночный spike и несколько
  spikes. Он проверяет отсутствие ложной специализации и подтверждающее
  качество выбранной топологии.
- Полнообъёмная опорная модель обучается один раз для каждого сочетания
  `dataset/seed/model` на всём внешнем обучающем разбиении и
  переиспользуется между бюджетами.
- Закон масштабирования
  `L(b)=L_full+A(b^{-alpha}-1)` оценивается устойчивой регрессией с
  бутстрэп-интервалами. Отчёт вычисляет бюджет для допустимой деградации 1%, 3%
  и 5% и маркирует слабые аппроксимации.
- Быстрый сценарий на реальных данных отдельно проверяет операционную
  корректность и научную эффективность. Это не позволяет одному seed
  ошибочно отклонить исправную реализацию только из-за отсутствия выбранной
  специализации.

Полный применимый набор проекта содержит `383 passed`. Два исторических файла
`test/test_feature_based.py` и `test/test_temporal.py` исключены из этого
запуска из-за существующих импортов `from core`, не связанных с PR. Аудит 86
исследовательских файлов не обнаружил токенов, серверных реквизитов или сырых
строк OpenML.

## 4. Анализ итогов: было / стало

| Было | Стало |
| --- | --- |
| Один критерий геометрии без отдельного контракта классификации | A10 учитывает тип основной метрики, вероятности, калибровку и полноту классов |
| `capped_leverage` применялся как общая политика | S.1 разрешает его только после независимой внутренней проверки |
| Bulk/spike существовал преимущественно как диагностика | B1/B2 материализуют экспертов с точным бюджетом, B3 безопасно выбирает топологию |
| Короткая проверка смешивала исполнимость и статистическую эффективность | Операционный smoke-критерий отделён от многоразового научного критерия |
| Качество сравнивалось без единого полнообъёмного якоря | Для каждой задачи и seed переиспользуется полнообъёмная опорная модель |
| Четырёх бюджетов недостаточно для закона масштабирования | Плотная сетка из десяти бюджетов и явные статусы качества аппроксимации |
| Этапы запускались отдельными сценариями без общего состояния | Типизированный граф из семи этапов поддерживает критерии перехода и возобновление |
| Прогресс подтверждался только тестами кода | Сохраняются синтетические и реальные CSV/JSON/PNG-артефакты и отчёты |
