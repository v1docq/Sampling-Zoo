# Отчёт о реализации исследовательской программы RMT

Дата: 12 августа 2026 года. Ветка:
`codex/rmt-classification-bulk-spike-program`.

## Выполненная работа

1. Добавлен защищённый селектор геометрии A10 для классификации с отдельными
   ограничениями для ROC AUC, log loss, Brier score, ECE, `F1 macro` и
   минимальной полноты класса.
2. Добавлен селектор этапа S.1 между `uniform` и `capped_leverage` с
   раздельными внутренними фолдами и безопасным возвратом к равномерной
   выборке.
3. Реализованы точные по бюджету топологии B1 и B2, а также B3, который
   выбирает B0/B1/B2 без доступа к внешнему тесту.
4. Строгий синтетический критерий завершён на 1260 из 1260 запусков: 94,12%
   выбранных специализаций победили B0, медианный выигрыш составил 19,27%, а
   худшее подтверждающее ухудшение — 0,0904%.
5. Реальный контур проверен для регрессии и многоклассовой классификации.
   Вероятности классов выравниваются, общий бюджет сохраняется, а классы
   восстанавливаются обменом строк без дублирования.
6. Добавлена полнообъёмная опорная модель для каждого сочетания
   `dataset/seed/model`. Она обучается на всём внешнем обучающем разбиении и
   переиспользуется между бюджетами.
7. Добавлен слой законов масштабирования с полнообъёмным якорем, устойчивой
   аппроксимацией, бутстрэп-интервалами и оценкой бюджета для деградации 1%,
   3% и 5%.
8. Добавлен типизированный семиэтапный исполнитель с графом зависимостей,
   жёсткими критериями перехода, инкрементальным состоянием и проверкой
   совместимости возобновления.
9. Добавлен короткий серверный сценарий
   `rmt_bulk_spike_research_smoke.py`. Он последовательно проверяет безопасность
   классификационного селектора на бинарной и многоклассовой задачах, а затем
   проверяет точное соблюдение бюджета в bulk/spike-топологиях для регрессии и
   классификации. Состояние сохраняется атомарно после каждого этапа.

## Проверка

- целевой набор архитектурных и численных тестов: `136 passed`;
- полный применимый набор проекта: `382 passed`;
- `py_compile` для новых исполнителей, контрактов и анализаторов: пройден;
- графики проверочных запусков на реальных данных и для законов
  масштабирования: проверены визуально;
- `test/test_feature_based.py` и `test/test_temporal.py` исключены из полного
  запуска из-за существующих импортов `from core`, не связанных с этой
  веткой.

## Следующая точка

После публикации ветки серверный запуск начинается с этапа
`classification_geometry_guard`. Затем выполняется
`conditional_row_policy`; только после завершения обоих этапов и прохождения
классификационного критерия запускается `bulk_spike_pilot`.
