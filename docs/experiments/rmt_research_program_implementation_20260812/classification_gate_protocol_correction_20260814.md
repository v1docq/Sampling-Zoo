# Коррекция классификационного этапа RMT

## Наблюдение

Первый серверный запуск `classification_geometry_guard` сформировал 480 записей,
но научный критерий не был пройден. Внутри этапа зафиксировано 20 неуспешных
запусков для `vehicle` при бюджете 1%: пяти партициям выделялось по две строки,
хотя задача содержит четыре класса. Ещё в одном случае внешний тест показал
ухудшение log loss на 1,62% после выбора A5.

Этап `conditional_row_policy` независимо завершил 480 записей и прошёл свой
критерий. Его повторный расчёт не требуется.

## Принятые изменения

1. Число классификационных партиций ограничивается бюджетом сохранения классов.
2. При необходимости разрешается одна партиция.
3. Для классификации фактически включается жёсткое соблюдение минимального
   размера партиции.
4. В A10 нижняя граница доверительного интервала выигрыша по основной метрике
   должна быть неотрицательной.
5. Повтор `classification_geometry_guard` архивирует прежний результат,
   сохраняет `conditional_row_policy` и инвалидирует только зависимые этапы.

Контрфактический пересчёт строгого порога на имеющихся результатах дал 33 выбора
небазовой геометрии, долю выигрышей 93,94%, средний выигрыш 0,488% и худший
выигрыш -0,136%. Эти числа служат проверкой направления изменения, но не
заменяют повторный запуск после исправления бюджетной постановки.

## Точка продолжения

Повтор начинается с `classification_geometry_guard` в существующем каталоге
исследовательской программы. После прохождения критерия автоматически запускаются
этапы 3–7. Завершённый `conditional_row_policy` используется повторно.
