## 1. Почему появился этот PR

Первые серверные запуски семиэтапной RMT-программы выявили две ошибки
экспериментального протокола. При малом бюджете число классификационных партиций
могло быть несовместимо с обязательным сохранением классов. После устранения
этой проблемы этап `bulk_spike_pilot` показал второй сбой: целочисленные целевые
значения `diamonds` и `OnlineNewsPopularity` были ошибочно распознаны как
многоклассовые метки, хотя конфигурация явно задавала регрессию.

Из-за второй ошибки 100 из 320 записей пилота завершились техническим сбоем, а
научный критерий этапа нельзя интерпретировать как итоговый результат.

## 2. Что он меняет или стремится улучшить в текущей базе

PR делает бюджет классификационного семплирования зависимым от фактического
числа классов и доступного числа строк. Явный `cluster_target_type` становится
источником истины для определения типа задачи; автоматическое определение
используется только при значении `"auto"`.

Также добавлен безопасный повтор отдельных этапов исследовательской программы.
Уже проверенные независимые этапы переиспользуются, повреждённые результаты
архивируются, а зависимые этапы пересчитываются в установленном порядке.

## 3. За счёт каких решений и методов он это делает

- `ClassificationPartitionBudgetPlan` вычисляет допустимое число партиций из
  бюджета, числа классов и минимального числа представителей каждого класса;
- `RMTContractionTensorSampler` передаёт явный `cluster_target_type` в чистую
  функцию бюджетирования;
- `ResearchStageRetryPlan` формализует архивирование, сохранение независимых
  этапов и аннулирование зависимых результатов;
- строгий классификационный селектор требует неотрицательную нижнюю границу
  доверительного интервала основной метрики;
- тесты воспроизводят малый классификационный бюджет, целочисленную регрессию и
  переходы повторного запуска;
- диагностические отчёты сохраняют причины обоих серверных сбоев и правила
  повторного эксперимента.

Проверено 393 тестами полного применимого набора. Дополнительно пройдены
`py_compile` и `git diff --check`.

## 4. Анализ итогов: было / стало

| Было | Стало |
| --- | --- |
| Статичное число партиций могло нарушать покрытие классов при малом бюджете | Число партиций ограничивается проверенным бюджетным планом |
| Целочисленная регрессия могла быть распознана как многоклассовая задача | Явный `cluster_target_type="regression"` исключает классификационные ограничения |
| Повтор этапа требовал ручной очистки и мог затронуть валидные результаты | Повреждённый этап архивируется, независимые этапы сохраняются, зависимости пересчитываются |
| Научный критерий мог строиться по неполному набору записей | Переход к следующему этапу требует полного набора успешных запусков |
