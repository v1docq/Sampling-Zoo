# Коррекция контракта типа задачи для `bulk_spike_pilot`

## Наблюдаемый сбой

Повторный серверный запуск завершил этап `bulk_spike_pilot` со статусом
`completed_with_failures`: из 320 записей 220 были успешными, а 100 завершились
ошибкой. Все 80 конфигураций `diamonds` и 20 конфигураций
`OnlineNewsPopularity` были отклонены классификационной проверкой бюджета.

Целевые значения этих регрессионных задач являются целочисленными и имеют
высокую кардинальность. Внутренний вызов `type_of_target` интерпретировал их как
многоклассовые метки: например, для `diamonds` было получено 10 294 условных
класса. Поэтому бюджет от 388 до 7 767 строк ошибочно считался недостаточным для
сохранения всех классов.

## Причина

Эксперимент корректно передавал `cluster_target_type="regression"` через
`make_chunking_strategy_configs`. Однако
`build_classification_partition_budget_plan` повторно определял тип целевой
переменной в режиме `"auto"` и не учитывал явный контракт вызывающей стороны.

## Исправление

- `build_classification_partition_budget_plan` принимает
  `configured_target_type` и использует его как источник истины;
- автоматическое определение сохраняется только при значении `"auto"`;
- `RMTContractionTensorSampler` передаёт в бюджетный план собственный
  `cluster_target_type`;
- добавлены чистый тест бюджетного плана и интеграционный тест полного
  `RMTContractionTensorSampler.fit` на целочисленной регрессии.

## Проверка

- целевые проверки воспроизведения: 4 пройдены;
- расширенный контур RMT-классификации и маршрутизации: 61 проверка пройдена;
- полный применимый набор проекта: 393 проверки пройдены;
- `py_compile` и `git diff --check`: пройдены.

Файлы `test/test_feature_based.py` и `test/test_temporal.py` по-прежнему
исключены из полного запуска из-за ранее существовавших импортов `from core`, не
связанных с текущим изменением.

## Повторный запуск

Ошибочный каталог этапа 3 сохраняется в `retry_archive`. Повторный запуск
должен пересчитать только `bulk_spike_pilot` и зависимые от него этапы. Этапы
`classification_geometry_guard` и `conditional_row_policy`, уже завершённые с
результатом `passed`, должны быть переиспользованы без повторного вычисления.

Научный критерий предыдущего пилота не интерпретируется как итоговый: условие
`all_records_completed` нарушено. Порог доли побед специализированной топологии
80% при повторном запуске не меняется.
