# Малые бюджеты классификации и повтор этапов

Дата фиксации протокола: 14 августа 2026 года.

## Зачем потребовалась коррекция

В классификационном этапе исследовательской программы число партиций раньше
выбиралось независимо от доступного бюджета строк. Это нарушало требование
сохранения классов: при бюджете 1% четырёхклассовая задача могла получить две
строки на партицию, хотя для покрытия всех классов требовалось не менее четырёх.

Такая ошибка относится к постановке эксперимента, а не к качеству конкретной
геометрии маршрутизации. Поэтому число партиций теперь ограничивается до
кластеризации и выбора строк.

## План допустимого бюджета

Пусть:

- \(n\) — число обучающих строк;
- \(\rho\) — доля бюджета;
- \(K\) — число классов;
- \(m_c\) — минимальное число строк каждого класса в партиции.

Тогда целочисленный бюджет и минимальный размер партиции равны

\[
B = \max(1, \operatorname{round}(\rho n)),
\qquad
m = K m_c.
\]

Максимально допустимое число партиций:

\[
P_{\max} = \left\lfloor \frac{B}{m} \right\rfloor.
\]

`RMTContractionTensorSampler` ограничивает `n_partitions`, `min_partitions` и
`max_partitions` значением \(P_{\max}\). Для классификации автоматически
включается жёсткое соблюдение бюджета и кандидат `k=1`. Если \(P_{\max}=0\),
запуск завершается до кластеризации с явным сообщением о невозможности покрыть
классы. Если \(P_{\max}=1\), семплер строит одну партицию и сохраняет в ней все
классы. При нескольких партициях последующий выбор строк сохраняет все классы,
которые наблюдались в соответствующем исходном кластере.

Диагностика `classification_partition_budget_plan` содержит исходные и
фактические границы числа партиций, общий бюджет, минимальный размер партиции и
причину принятого решения.

## Строгий критерий A10

Для A10 внутренний выбор геометрии использует
`classification_primary_selection_margin=0.0`. Кандидат допускается только
тогда, когда нижняя граница доверительного интервала выигрыша по основной
метрике неотрицательна.

- для бинарной классификации основной метрикой остаётся ROC AUC;
- для многоклассовой классификации основной метрикой остаётся log loss;
- ограничения по Brier score, ECE, `F1 macro` и минимальной полноте класса не
  меняются;
- внешний научный критерий и тестовая выборка не участвуют во внутреннем выборе.

Параметры `roc_auc_absolute_margin` и `log_loss_relative_margin` сохранены для
совместимости общих сценариев. Строгий нулевой допуск включён только в
специализированной точке входа A10.

## Безопасный повтор этапа

Аргумент `--retry-stages` помечает указанный этап и все зависимые от него этапы
как требующие повторного выполнения. Их каталоги перемещаются в
`retry_archive/<retry_id>/`, а независимые завершённые этапы остаются в текущем
состоянии.

Для коррекции классификационного критерия используется команда:

```bash
python examples/benchmark/rmt_bulk_spike_research_program.py \
  --output-root /path/to/run_rmt_bulk_spike_program \
  --retry-stages classification_geometry_guard
```

При таком повторе `conditional_row_policy` не пересчитывается. После успешного
завершения классификационного этапа исполнитель продолжает
`bulk_spike_pilot`, `bulk_spike_confirmation`, `bulk_spike_full_grid`,
`dense_scaling_grid` и `final_analysis`.

Для каждого повтора создаётся `research_program_retry_<retry_id>.json`. В нём
зафиксированы запрошенные этапы, этапы со сброшенными результатами, перемещённые
каталоги и сохранённые независимые результаты.

## Проверяемые инварианты

1. Фактическое число партиций не превышает \(P_{\max}\).
2. Размер каждой классификационной партиции не меньше \(K m_c\).
3. Выбранные строки имеют точный общий бюджет.
4. Строгий A10 отклоняет кандидата с отрицательной нижней границей доверительного
   интервала.
5. Повтор этапа архивирует старые артефакты и сбрасывает результаты всего
   зависимого поддерева.
6. Независимый завершённый этап не запускается повторно.
